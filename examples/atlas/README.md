# Atlas acceptance example

Atlas is a sample multi-screen interface used to exercise design generation, component states, an isolated Interactive App, motion/QA, and browser navigation/freshness. It illustrates what the system can produce; it is not a ready-made business application or a complete visual/browser regression benchmark.

Suggested learning sequence: design → states → interactive → motion → qa → browser → browser-test → status. Browser acceptance and source freshness are separate results. A minimal source-binding fixture does not establish a complete visual export or complete control behavior.
