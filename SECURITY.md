# Security

Do not report suspected security vulnerabilities in public Issues, pull requests, or discussions. Do not publish credentials, private Figma documents, or local exports.

Once GitHub Private vulnerability reporting is enabled, use the repository's **Security and quality** (or **Security**) tab → **Report a vulnerability** to submit a private report. Include the affected release, reproduction steps, and impact without exposing other users' data. Ordinary bugs and setup problems belong in Issues.

The repository has not been published and private reporting is **not yet enabled**. The owner must enable it immediately when repository visibility becomes public; see the [launch checklist](docs/LAUNCH_CHECKLIST.md). No email contact or response-time guarantee is invented. If the private reporting flow is unavailable, do not post vulnerability details publicly; wait for the private flow.

The initial beta is the only planned supported public release. Use the localhost bridge and review provider requests before sharing confidential designs. Never fix setup by disabling security software or posting secrets.
